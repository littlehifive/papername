Papername privacy

Papername reads bibliographic metadata on HTTP(S) pages solely to name the academic PDF you download. Automatic coverage across publishers, university proxies, and institution-specific repositories requires broad Chrome site access, which Chrome discloses at install or update.

Everything stays in your browser

Filenames are generated entirely on your device from the page you are viewing. Papername has no server, sends no paper content anywhere, and collects no usage data. It does not inspect your Downloads folder or retain a download library.

Your filename format, including any custom arrangement of authors, year, title, and fixed text, is stored only in Chrome's local extension storage for this browser profile.

Site access

Page metadata is processed locally and retained only as a short-lived article context. Papername does not modify pages. On unrecognized sites, it watches only citation metadata in the document head; tested academic sources may also expose metadata elsewhere in the page. You can change Papername to “On click” or selected sites, or disable its access, through Chrome's extension Site access controls. Doing so reduces automatic coverage.

For a few recognizable repository PDF routes, an explicit action may retrieve the public article-record page from the same site. Papername does not read or upload the PDF itself. ResearchGate is excluded because its current terms prohibit this kind of browser-add-on access.

When you activate a Google Scholar side link marked “[PDF],” Papername reads the visible result title, author line, year, and selected link locally so that many library-proxy downloads can be matched. It does not automate searches or retain a search history.
