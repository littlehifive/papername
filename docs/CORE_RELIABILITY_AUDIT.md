# Core PDF reliability audit

Status: Complete. Started 2026-09-09 and completed 2026-09-11 (America/New_York).

## Acceptance plan

1. Reproduce the reported SAGE article → reader → PDF failure in ordinary Chrome, and retain a minimal regression fixture from the observed bibliographic fields and URLs.
2. Choose one paper per currently listed source family using a recorded random index from a visible results/recent-papers list. Test PubMed and PMC separately. Add three Google Scholar routes: a publisher PDF, a repository PDF, and a publisher landing page followed by its PDF. Include one institution-specific repository.
3. For each selected paper, record the landing URL, observed authors/year, PDF destination and final route, article and PDF popup status, actual downloaded filename, and access blockers. A supported host or a successful extraction alone is not a download pass.
4. Verify the three local naming presets, same-tab and new-tab readers, download redirects, duplicate names, missing metadata, supplements, unrelated PDFs, and disabled mode in controlled browser/decision regression tests. Verify the optional gist path falls back promptly without requiring a paid API call.
5. Measure popup initialization and test late metadata, repeated opening, busy pages, and service-worker restart. Fix reproducible product failures and distinguish automation latency from extension latency.
6. Run `pnpm check`, rebuild the extension, reload the installed development extension, and repeat failing live flows. Publish the evidence and remaining limitations here. Never count a CAPTCHA, paywall, or inaccessible PDF as a pass.

## Coverage ledger

### SAGE retest and first fix batch (2026-09-09, 21:08 EDT)

The installed unpacked extension was reloaded from `apps/extension/.output/chrome-mv3` using Chrome's extension details page; Chrome displayed **Reloaded**. After reopening the article, both article and EPUB-reader popups displayed **Ready to rename**. Clicking the reader's **Download PDF** produced **Fransen & Schewel (2026).pdf — 1,331 KB — Done** in Chrome's download history. The reported live SAGE failure is fixed.

Regression evidence: the observed SAGE fixture initially failed all five cases (unchanged main PDF, lost reader/PDF readiness, and misnamed referenced PDF). These now pass, with added negative tests for conflicting identities, another publisher, a DOI prefix collision, supplements, and expired context. Two new real-extension Playwright tests also failed before the timing fixes: continuously mutating pages never published late metadata within 1.5 seconds, and an already-open popup stayed on **No paper found yet** after capture. Both pass after the fix.

`pnpm check` passed: formatting, typechecking, 126 unit/HTTP tests, 3 D1 tests, production build, and 8 Playwright tests. This validates the first fix batch; it does not establish live coverage for the pending sources below.

## Baseline checks

- Final `pnpm check` passed on 2026-09-11: formatting, typechecking, 140 unit/HTTP tests, 3 D1 tests, production builds for the extension and Worker, and all 11 Playwright tests.
- The controlled popup regression opens the popup three times with a 1-second readiness deadline, forcibly stops Chrome's extension service workers through CDP, then verifies the next popup becomes ready within 1.5 seconds. It passes. The late-metadata and continuously mutating-page races also pass.
- Existing Playwright coverage includes context injection, popup controls, OSF primary-file capture and signed-storage matching, Google Scholar selection, source-family injection, download matching, and popup/service-worker responsiveness. It supplements rather than replaces the live source matrix.
- The initial sandboxed Chromium launch failed before tests could run; this is an execution-environment limitation, not an extension failure.
- Popup opened promptly in the ordinary Chrome SAGE reproduction. The first native accessibility inventory took 92 seconds; that tool latency is not evidence that Papername itself took 92 seconds to open.
